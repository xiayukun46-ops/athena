## 1. 产品定位

### 1.1 Athena 是什么

Athena 是一个 **AI 驱动的全球知识平台**。它将全球公开信息持续转化为结构化、可查询、可溯源的知识图谱，通过搜索和问答两种方式向用户提供可信的知识服务。

### 1.2 Athena 不是什么

清晰地定义"不是"比"是"更重要。以下是常见误解：

**不是新闻聚合器**。Feedly、Flipboard、今日头条聚合的是"文章"，Athena 聚合的是"知识"。前者给你一个标题列表，后者给你一个实体关系网络。内容采集成管道是 Athena 的输入层，不是产品层。

**不是 AI 聊天机器人**。ChatGPT、Claude 的交互模式是对话。Athena 的交互模式是"查询-答案-溯源"。对话可能是 Athena 的一种交互方式，但不是产品定义。Athena 的核心产品是知识图谱 + 可溯源问答——不是让你和 AI 闲聊。

**不是搜索引擎**。Google、Bing 的输入是关键词，输出是链接列表。Athena 的输入可以是关键词或自然语言问题，输出是结构化答案 + 来源引用 + 知识图谱浏览。搜索引擎告诉你"哪里可能有答案"，Athena 告诉你"答案是什么，谁说的，可信度多高"。

**不是百科全书**。Wikipedia 是人工编辑的结构化知识，有明确的完成标准和编辑规范。Athena 是 AI 自动提取 + 持续更新的活知识图谱，没有"写完"的概念。

### 1.3 定位公式

```
Athena = Wikipedia 的广度 × Google 的实时性 × ChatGPT 的理解力 × 学术论文的溯源性
```

六个字概括：**可信、结构化、开放**。

## 2. 市场分析

### 2.1 问题空间

全球知识市场存在四个结构性的供需失衡：

**失衡一：信息生产速度 >> 人类消费速度**

每天产生 250 万篇新闻文章、50 万篇学术论文、5 亿条社交媒体帖子。一个人类读者穷尽一生也无法读完一天产生的信息。信息不是稀缺资源，**理解信息的能力**才是。

**失衡二：AI 生成内容的爆发加剧了可信度危机**

2026 年，互联网上超过 20% 的内容由 AI 生成。深度伪造、AI 幻觉、算法偏见使"什么是真的"成为比"什么是最新的"更根本的问题。现有的信息平台（搜索引擎、社交媒体）没有解决可信度问题——它们的商业模式依赖的是点击量，不是准确度。

**失衡三：知识的语言壁垒**

全球 80% 的学术出版物是英文，但全球 75% 的人口不以英语为母语。一个只会说斯瓦希里语的肯尼亚学生和一个只会说中文的中国医生，几乎无法访问相同的知识库——尽管知识本身是语言无关的。

**失衡四：知识的孤岛效应**

一篇关于 CRISPR 基因编辑的 Nature 论文、一篇关于基因治疗定价的《金融时报》报道、一条关于 FDA 审批的政府公告——这三者讨论同一个主题，但分别存在于学术数据库、新闻付费墙和政府网站中，没有任何系统把它们连接起来。知识的价值不在单个文档中，而在文档之间的**关系**中。

### 2.2 市场规模

| 细分市场 | 全球规模 (2026) | 年增长率 | Athena 切入方式 |
|----------|---------------|----------|----------------|
| 搜索引擎 | $250B | 8% | 不直接竞争，但 Athena 的搜索 API 可作为增强层 |
| 知识管理软件 | $45B | 12% | Athena 提供知识图谱基础设施 |
| AI 问答 / 对话 | $30B | 35% | Athena 提供可信溯源问答——差异化定位 |
| 学术搜索 | $3B | 10% | Athena 初期核心用户群 |
| 新闻聚合 | $15B | 5% | Athena 提供结构化新闻知识 API |
| 开发者 API 市场 | $20B | 18% | Athena 的长期平台收入来源 |

**Athena 的可寻址市场 (TAM)**：以知识图谱为基础设施层的所有应用场景。初期聚焦学术研究和调查新闻两个垂直领域（合计约 $5B），中期覆盖知识工作和企业智能（$50B+），长期成为通用知识基础设施层。

### 2.3 市场时机

2026 年是启动 Athena 的最佳窗口期，原因有三：

1. **LLM 能力成熟**：GPT-5 和 Claude-4 级别的模型在多语言理解、实体识别、关系抽取上的准确率已达到实用门槛（85%+），使自动化知识提取成为可能。
2. **AI 信任危机**：ChatGPT 级别的流畅文本泛滥，用户对"看起来像真的但无法验证"的信息的疲劳感快速上升，"可溯源"正在成为一个差异化价值。
3. **基础设施成本下降**：Embedding 和向量搜索的成本在过去 18 个月下降了 80%，使十亿级知识图谱的经济可行性成立。

## 3. 竞争格局

### 3.1 竞争矩阵

按两个维度划分：**知识结构化程度**（横轴）和**信息来源溯源性**（纵轴）。

```
溯源性强 ↑
         │  Wikipedia     ★ Athena
         │  (结构化,有出处) (结构化+AI,有出处+置信度)
         │
         │  Google Scholar  Perplexity
         │  (无结构,有出处)  (无结构,有出处+AI)
         │
         │  Google Search   ChatGPT
         │  (无结构,无出处)  (无结构,无出处+流畅)
         │
         └──────────────────────────→ 结构化程度强
```

### 3.2 竞品深度分析

**Google Knowledge Graph**

- 优势：规模最大（50B+ 事实）、与搜索深度集成、Google 的工程能力
- 劣势：封闭（无公开 API）、面向搜索摘要而非深度研究、不支持溯源、中文/小语种覆盖弱
- **Athena 的差异**：开放 API、Statement 溯源层、100+ 语言目标

**Wikipedia + Wikidata**

- 优势：开放、社区治理、结构化（Wikidata）、多语言
- 劣势：人工编辑速度慢（重大事件可能需要数天才有条目）、覆盖不均衡（非洲/南亚内容极少）、无 AI 辅助
- **Athena 的差异**：AI 自动提取（分钟级更新）、覆盖均衡（不以编辑者分布为转移）

**ChatGPT / Claude**

- 优势：流畅性极高、零学习成本、多模态、快速迭代
- 劣势：不可溯源、幻觉问题未解决、无结构化知识、不可编程查询
- **Athena 的差异**：可溯源、每条声明有出处、知识图谱可编程查询、不同观点并存

**Perplexity**

- 优势：AI 答案 + 来源链接、用户体验好、增长快
- 劣势：无结构化知识（答案非实体关系）、不标注置信度、封闭平台
- **Athena 的差异**：结构化知识图谱 + 溯源声明 + 开放 API

**Elicit / Consensus（学术搜索）**

- 优势：专注学术论文、AI 辅助文献综述
- 劣势：只覆盖学术领域、不处理新闻/报告/政府数据
- **Athena 的差异**：跨域知识连接（一篇论文 ↔ 一篇新闻报道 ↔ 一份政府文件）

### 3.3 竞争策略：不竞争

Athena 的核心竞争策略不是"比别人做得更好"，而是"做别人不做的事"：

1. **开放平台 vs 围墙花园**：Google、ChatGPT、Perplexity 都是封闭生态。Athena 以 API 和 Plugin 为第一优先级。
2. **知识基础设施 vs 信息产品**：Athena 定位为"知识的 AWS"，不是"知识的 iPhone"。我们不追求完美的用户界面，我们追求完美的 API。
3. **可信 vs 流畅**：当所有人都追求 AI 输出的流畅度时，Athena 追求可溯源性和置信度标注。这是逆势而为的定位，也是唯一可持续的护城河。

## 4. 产品架构

### 4.1 三层产品模型

```
┌─────────────────────────────────────────┐
│         Application Layer               │
│  Web App │ Mobile App │ 3rd-Party Apps  │  ← 用户直接交互层
├─────────────────────────────────────────┤
│         Platform Layer                  │
│  REST API │ GraphQL │ Webhook │ SDK     │  ← 开发者接入层
├─────────────────────────────────────────┤
│         Knowledge Layer                 │
│  Knowledge Graph │ Q&A Engine │ Search  │  ← 核心能力层
├─────────────────────────────────────────┤
│         Data Layer                      │
│  Collector │ AI Pipeline │ Storage      │  ← 数据引擎层
└─────────────────────────────────────────┘
```

### 4.2 三条产品线

**产品线 A：Knowledge Graph（知识图谱）**

面向深度研究。用户浏览实体关系网络、查看实体时间线、对比不同来源的声明。

核心功能：
- 实体搜索与详情（多语言名称、属性、关联实体）
- 关系图浏览（N 度邻居、路径查询、子图探索）
- 声明溯源（原文摘录、来源链接、置信度评分）
- 时间线（实体属性随时间的变化）
- 趋势检测（近期被高频提及的实体和主题）

**产品线 B：Q&A Engine（可信问答）**

面向快速获取答案。用户用自然语言提问，得到有出处的结构化答案。

核心功能：
- 自然语言提问（支持 100+ 语言）
- 结构化答案（实体名、属性值、关系描述）
- 多源引用（每条答案附带 1-5 个来源链接）
- 置信度标注（帮助用户判断答案的可信程度）
- 观点对比（对争议性问题展示不同来源的说法）
- 追问与澄清（多轮对话深入探索）

**产品线 C：Discovery（知识发现）**

面向意外发现。用户不带着明确问题，而是探索他们不知道自己不知道的知识。

核心功能：
- 实体间意外关联（"A 和 B 之间有一条你没想到的连接"）
- 趋势主题（某领域近期的热点话题和关键实体）
- 知识脉络（一个事件的前因后果链）
- 个性化每日简报（基于用户兴趣的知识推送，Phase 4+）

### 4.3 阶段性 Product-Market Fit

| 阶段 | 目标 PMF | 验证指标 |
|------|----------|----------|
| Phase 2-3 | 知识提取质量 PMF | 实体准确率 ≥ 85%，关系准确率 ≥ 80% |
| Phase 4 Alpha | 研究用户 PMF | 研究者周活跃率 ≥ 40%，平均会话时长 ≥ 8min |
| Phase 4 GA | 知识工作者 PMF | DAU ≥ 10K，NPS ≥ 40 |
| Phase 5 | 开发者 PMF | API 日调用 ≥ 1M，开发者留存率 ≥ 60% |

## 5. 用户分层与获取策略

### 5.1 用户分层

```
第一层（Phase 4）：知识工作者
  - 研究者、记者、分析师、学生
  - 获取方式：学术社区推广、Journalist 工具推荐、大学合作
  - 100K 用户即可验证 PMF

第二层（Phase 4-5）：专业用户
  - 律师、医生、工程师、投资人
  - 获取方式：垂直领域集成（法律数据库、金融终端、医疗文献系统）
  - 自然增长 + 合作伙伴渠道

第三层（Phase 5+）：大众用户
  - 任何有求知需求的人
  - 获取方式：第三方应用自然引流（通过 API 集成）
  - Athena 不直接获取大众用户——合作伙伴替我们获取
```

### 5.2 为什么先服务研究者

1. **容忍度高**：研究者习惯于验证信息，容忍 AI 的不完美
2. **价值密度高**：一次深度研究回答的价值 > 100 次碎片化浏览
3. **反馈质量高**：专业用户能指出"这个实体关系不对"，帮助迭代知识模型
4. **传播杠杆高**：研究者发表文章时会引用 Athena，自带学术传播
5. **竞争真空**：学术搜索工具（Google Scholar, Elicit）不做新闻；新闻聚合器不做学术。Athena 的跨域连接是独特价值

### 5.3 不做什么样的增长

- 不做病毒营销 / 社交裂变（因为不做社交功能）
- 不买量（SEO 自然增长 + 学术引用 + 合作伙伴分发）
- 不做 B2C 广告投放（初期每一分钱投在工程上）

## 6. Go-to-Market 策略

### 6.1 Phase 4 Alpha（2027 Q3）

**目标**: 获取 500-1000 名种子用户，验证核心价值。

**渠道**:
- 学术社区：与 5-10 所大学合作（Stanford, MIT, 清华, Oxford），教授推荐给研究生使用
- 记者社区：与 IRE (Investigative Reporters & Editors)、GIJN 合作
- 开源社区：在 GitHub Trending、Hacker News 上宣布项目

**价值主张**: "从 100 篇文章中梳理人物关系网络，原来是 3 天的工作，现在是 3 分钟。"

### 6.2 Phase 4 GA（2027 Q4）

**目标**: 从种子用户扩展到 10K-50K 活跃用户。

**渠道**:
- 内容营销：发布使用 Athena 完成的研究案例（"How We Mapped the Global Supply Chain in 2 Hours"）
- SEO：Athena 的每个实体页面本质上是一个 SEO-optimized 知识页面
- 学术引用：使用者发表的论文中引用 Athena，形成学术传播闭环

### 6.3 Phase 5（2028+）

**目标**: 从自有产品扩展到平台生态。核心增长引擎从"我们获取用户"切换到"合作伙伴替我们获取用户"。

**渠道**:
- API 文档和 SDK（降低集成门槛）
- 开发者社区（Hackathon、案例展示、开发者认证）
- 插件市场（第三方开发者可获得收入分成）
- 企业销售（面向需要私有部署的金融、医疗、法律机构）

## 7. 商业模式

### 7.1 收入来源

Athena 采用多层次收入模型，各层次按阶段开放：

| 层次 | 模式 | 目标客户 | 开放阶段 |
|------|------|----------|----------|
| Free Tier | 免费使用 | 个人用户、学生 | Phase 4 |
| Pro Tier | 月度订阅 $10-30 | 专业用户（研究者、记者） | Phase 4 |
| API Pay-as-you-go | 按调用量计费 | 开发者、中小企业 | Phase 5 |
| Enterprise | 年度合同 | 大型企业、机构 | Phase 5 |
| Plugin Market | 交易佣金 15-30% | 插件开发者、用户 | Phase 5 |
| Private Deployment | 一次性许可费 | 金融、医疗、政府 | Phase 5+ |

### 7.2 定价原则

1. **Free Tier 永远存在**：个人求知不应被付费墙阻挡。Free Tier 提供基本搜索和问答，但有速率限制。
2. **Pro 定价参考学术工具**：$15/月（学生）、$30/月（专业用户）——与 Spotify、Netflix 处于同一心理价位。
3. **API 定价透明可预测**：按每 1000 次调用计费，价格公开在网站上。不要求"联系我们获取报价"。
4. **开源核心免费**：Athena 核心引擎开源（Apache 2.0），Enterprise 层级卖的是托管服务、SLA 和私有部署支持。

### 7.3 可持续性路径

Athena 不以短期盈利为目标。Phase 0-4 完全由初始资金（或开源社区贡献）支持。Phase 5 启动商业化。

**盈亏平衡点预估**：Phase 5 启动后 12-18 个月。需要约 500 付费 Pro 用户 + 50 个 API 付费客户 + 3-5 个 Enterprise 客户。

## 8. 平台策略

### 8.1 API First 的产品哲学

Athena 的产品优先顺序：

```
1. API（开发者可通过编程方式使用所有功能）
2. Web App（面向终端用户的参考实现）
3. Mobile App（便利性补充，不早于 Phase 5）
```

**为什么 API 第一**：

- API 是不可替代的——你可以用 React/Vue/Svelte 重写 UI，但不能重写知识图谱 API
- API 带来网络效应——每个基于 Athena API 构建的应用都是 Athena 的免费分销渠道
- API 是防御性护城河——用户界面可以被复制，但 API 背后的知识图谱不能

### 8.2 插件生态

Athena 的五类插件（Source、Processor、Storage、AI、UI）在 Phase 5 对第三方开放。插件市场是 Athena 的"App Store"。

**开发者激励**：
- 免费插件获得社区声誉
- 付费插件获得 70-85% 收入分成
- Top 插件开发者的企业级支持服务

## 9. 分阶段交付计划

### Phase 0 — Foundation（当前）

**产品层面做什么**：定义产品愿景、策略、定位。不做任何功能。

**产品层面不做什么**：不写代码、不做原型、不做用户调研（无产品可测）。

### Phase 1 — Core Infrastructure（2026 Q4 - 2027 Q1）

**产品交付**：无终端用户产品。

**内部交付**：内容采集管道可运行、数据库就绪、事件总线就绪。产品团队开始设计 Phase 4 的用户体验。

### Phase 2 — Domain Core（2027 Q1 - Q2）

**产品交付**：
- 实体搜索 API（内部可用）
- 基础搜索 API（全文 + 向量）
- 知识图谱浏览（内部工具）

**用户**：内部团队验证知识质量。不对外。

### Phase 3 — AI Integration（2027 Q2 - Q3）

**产品交付**：
- 可信问答 API（内部 Alpha）
- Statement 审核工具（内部使用）
- AI 评测仪表盘

**用户**：50-100 名邀请制 Alpha 测试者（研究者、记者）

### Phase 4 — User Experience（2027 Q3 - Q4）

**产品交付**：
- Web App 公开发布
- Pro 订阅上线
- 移动端（TBD，取决于 RFC-006 决议）

**用户**：公开发布。目标 10K+ 注册用户，1K+ 付费用户。

**关键里程碑**：
- M1: Alpha 发布（邀请制，500 用户）
- M2: Public Beta（开放注册）
- M3: GA 发布（Pro 订阅可用）
- M4: 10K MAU

### Phase 5 — Ecosystem（2028+）

**产品交付**：
- 公开 API + SDK（Python, TypeScript, Dart）
- 插件市场
- 第三方集成（Slack, Notion, Obsidian）
- Enterprise 方案

## 10. 取舍与决策框架

### 10.1 优先级排序

当资源有限时，按以下顺序分配：

```
1. 知识质量（准确率、召回率、溯源完整度）
2. 平台开放性（API 完整度、文档质量）
3. 性能与可用性（延迟、可用率）
4. 用户界面美观度
5. 功能广度（更多垂直领域、更多语言）
6. 增长与营销
```

### 10.2 经典取舍场景

| 场景 | 选择 | 理由 |
|------|------|------|
| 提升 AI 准确率 vs 增加新语言 | **提升准确率** | 30 种语言 70% 准确率不如 10 种语言 90% 准确率 |
| 免费用户功能 vs Pro 功能 | **先做免费** | Phase 4 的目标是验证 PMF，不是收入 |
| 更多实体类型 vs 更深的关系提取 | **更深的关系** | 8 种实体类型已足够。关系质量是差异化的关键 |
| 更好的推荐 vs 更好的搜索 | **更好的搜索** | 用户带着问题来，搜索是第一入口 |

### 10.3 "不做什么"清单（扩展版）

除了 [00-vision.md](00-vision.md) 中定义的 Non-goals，产品层面额外明确：

- 不做内容创作工具（编辑器、发布器）
- 不做团队协作功能（共享文件夹、评论、权限管理）——Phase 5 Enterprise 层可能考虑
- 不做离线模式（Athena 的核心价值依赖实时知识）
- 不做 Podcast / 视频内容索引（Phase 5+ 多模态后考虑）
- 不做广告（收入模型以订阅和 API 为主）
- 不卖用户数据（这是底线，也是与 Google/Facebook 的根本区别）

## 11. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| AI 提取质量不达标（<70%） | 中 | 高 | Phase 2 集中资源优化 AI 管道；人工审核补位 |
| 大厂复制（Google 推出类似功能） | 高 | 中 | 开放生态是护城河（Google 不会开放 Knowledge Graph） |
| 用户不习惯"置信度"概念 | 中 | 中 | UI 设计降低认知门槛（用颜色/图标代替数字） |
| API 滥用（恶意调用） | 高 | 中 | 速率限制 + 认证 + 滥用检测 |
| 内容版权纠纷 | 中 | 高 | 只索引公开可访问的内容；提供原始链接（不替代原网站） |
| AI 幻觉导致的信誉危机 | 高 | 高 | 置信度标注 + 溯源 + 争议保留（不是隐藏不确定性） |

## 12. 成功标准

### Phase 4 Alpha（2027 Q3）

- [ ] 500 名邀请制用户
- [ ] 周活跃率 ≥ 30%
- [ ] 搜索到实体详情的转化率 ≥ 20%
- [ ] NPS ≥ 30
- [ ] 用户反馈中"可溯源"被提及为 Top 3 理由

- [ ] 10K 注册用户
- [ ] 1K 付费用户（Pro Tier）
- [ ] DAU ≥ 2K
- [ ] 平均会话时长 ≥ 8min
- [ ] 搜索引擎自然流量占比 ≥ 30%
- [ ] NPS ≥ 40

- [ ] 100 个第三方应用使用 Athena API
- [ ] API 日调用量 ≥ 1M
- [ ] 插件市场 ≥ 50 个活跃插件
- [ ] 月经常性收入 (MRR) ≥ $50K
- [ ] 毛利率 ≥ 50%
