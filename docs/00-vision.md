## 1. Vision（愿景）

### 简洁表述

**让每个人都能以最自然的方式获取最准确的知识。一个以权威来源为基础，能够持续收集、验证、组织、关联、搜索和长期管理全球知识的 AI 平台。**

### 完整表述

Athena 是一个 **AI-Powered Global Knowledge Operating System（AI 驱动的全球知识操作系统）**。它——一个 AI 驱动的基础设施层，将人类产生的所有公开信息转化为结构化、可查询、可推理、可溯源的知识网络。在这个网络中，任何人——无论语言、地域、专业背景——都可以用自然语言提问，获得有据可查的答案，追溯每一条信息的原始来源，并看到不同观点的全景。

我们相信，人类的下一个重大飞跃不是制造更强大的 AI，而是让 AI 帮助人类更好地理解已有的知识。知识的不平等——谁掌握信息、谁能理解信息——是当今世界最深层的结构性不公之一。Athena 的终极目标，是让知识变得像水和电一样，成为人人可及的基础设施。

### 十年后的世界

2036 年，Athena 已经不再是一个"产品"，而是一层基础设施。就像今天的 DNS 解析域名、CDN 分发内容、AWS 运行计算一样，Athena 运行着全球的知识层。当一位肯尼亚的中学生在手机上用斯瓦希里语问"量子计算是如何工作的"——她不会得到 10 个蓝色链接、不会得到一段没有出处的 AI 流畅回答、不会被迫阅读英文维基百科。她得到的是一个结构化的答案，附带来自全球多个来源的证据，标注了每条信息的置信度，并展示了对同一问题的不同科学观点。

这就是 Athena 存在的唯一理由。

## 2. Mission（使命）

### 我们做什么

Athena 的使命是将全球公开信息持续地、自动化地、可信地转化为结构化知识。具体而言，我们做三件事：

**第一，聚合与理解**

我们从全球数十万内容源（新闻、论文、报告、政府数据、社交媒体）实时采集信息，通过 AI 管道理解其内容——不仅是关键词匹配，而是实体识别、关系抽取、事件脉络、情感分析和跨语言对齐。每一篇文章不只被"索引"，而是被"理解"。

**第二，结构化与连接**

我们将理解后的信息组织为知识图谱：实体（人、组织、地点、事件、概念）、关系（雇佣、位于、参与、导致、引用）、声明（谁在哪个来源中说了什么）。知识之间互相连接——一篇 Nature 论文可能与三个月前 CNN 的报道讨论同一个蛋白质，而我们的系统自动建立这种连接。

**第三，查询与溯源**

我们提供两种获取知识的方式：搜索和问答。搜索让你找到最相关的实体和文章；问答让你用自然语言提问，得到有出处的答案。每一条信息都可以一键追溯到原始来源。如果多个来源对同一事实有不同说法，我们展示全景而非单一的"正确答案"。

### 我们如何做

- **AI 原生**：AI 不是附加功能，而是数据管道的默认处理方式。从采集到清洗到提取到问答——AI 贯穿始终。
- **持续进化**：知识不是一次性产品，而是持续更新的活体。新文章不断进入系统，知识图谱不断演化，旧知识可能被新证据推翻。
- **开放架构**：Athena 从第一天就以 Platform 的方式构建——核心能力通过 API 暴露，第三方可以基于 Athena 构建自己的应用。
- **十年工程**：我们不追求 3 个月的 MVP，而是按照 10 年尺度设计架构、治理和文档体系。慢而稳，不破不立。

## 3. Core Values（核心价值观）

Athena 的核心价值观不是贴在墙上的口号，而是每天指导设计和开发的决策框架。

### 3.1 Truth over Fluency（真相优先于流畅）

在 AI 时代，流畅的文本极度廉价。任何模型都可以生成读起来像真的内容。Athena 的价值不在于"说得好听"，而在于"说得有据"。我们宁可给用户一个"置信度 0.6，来源 3 篇"的朴素答案，也不给一个没有出处的华丽回答。

**决策影响**：
- 每条知识必须有 Statement（溯源声明）支撑
- 冲突的观点并存，不强行统一
- 置信度始终可见，不隐藏不确定性

### 3.2 Understanding over Aggregation（理解优先于聚合）

收集信息是 2005 年的问题。理解信息是 2026 年的问题。Athena 不做更好的 RSS Reader——我们做的是让机器真正理解一篇文章讲了什么、提到了谁、表达了什么关系、与前后的文章有什么联系。

**决策影响**：
- 数据管道以语义理解为目标，不以关键词索引为目标
- 实体链接和关系抽取是核心能力，不是可选功能
- 搜索返回的是实体和关系，不只是文档列表

### 3.3 Openness over Control（开放优先于控制）

Athena 是基础设施，不是围墙花园。我们没有兴趣把用户锁在我们的界面里。我们的目标是让其他开发者、研究者、企业能基于 Athena 构建自己的应用——就像有人基于 Google Maps 构建 Uber、有人基于 AWS 构建 Netflix。

**决策影响**：
- API First——所有功能通过 API 暴露
- Plugin First——扩展能力通过插件提供
- 不做社交功能（评论、点赞、分享）——那不是基础设施该做的事

### 3.4 Long-term over Short-term（长期优先于短期）

Athena 是一个 10 年项目。我们做的每一个架构决策，都要回答一个问题："10 年后回头看，这个选择还站得住吗？"如果答案是否定的，即使它能让我们快 3 个月，我们也拒绝。

**决策影响**：
- Modular Monolith → 微服务的渐进路径
- Plugin 接口预留给从未见过的扩展场景
- 文档体系支撑 100+ 人的团队
- 测试金字塔保证 10 年持续重构的安全网

### 3.5 Diversity over Consensus（多元优先于共识）

在知识领域，"正确答案"往往是暂时的、有偏的、被主流叙事主导的。Athena 保留知识的多面性：当两个权威来源对同一事实有不同说法时，我们展示两种说法及其各自的支持证据，而不是替用户选择"谁是错的"。

**决策影响**：
- Statement 冲突保留机制
- 来源可信度是展示给用户的元数据，不是内部黑箱分数
- 少数派观点保留，用户可以按观点过滤

## 4. Long-term Goal（长期目标）

### 十年目标（到 2036 年）

**Athena 成为全球知识的开放基础设施层。**

具体而言：

1. **覆盖规模**：索引全球 100+ 种语言的 1,000,000+ 内容源，知识图谱包含 10 亿+ 实体和 100 亿+ 关系
2. **用户规模**：每月服务 1 亿+ 独立用户，其中 60% 通过第三方应用间接使用 Athena API
3. **开发者生态**：10,000+ 第三方开发者基于 Athena API 构建应用，涵盖教育、研究、新闻、金融、医疗等垂直领域
4. **知识质量**：核心知识图谱的准确率达到 95%+（人类专家评估），Statement 审核覆盖率达到 100%
5. **开放标准**：Athena 的知识表示格式（Knowledge Triangle Model）成为开放标准，被至少 3 个其他知识平台采用
6. **可持续性**：项目实现财务自给自足，通过 API 订阅、企业授权、插件市场三种模式

### 五年里程碑（到 2031 年）

- 索引 50+ 种语言，覆盖 100,000+ 内容源
- 知识图谱 5 亿+ 实体，50 亿+ 关系
- Web、Mobile、API 三个产品形态均可使用
- 插件市场有 500+ 活跃插件
- 1000+ 第三方开发者

### 两年里程碑（到 2028 年）

- Phase 0-2 完成：完整的内容管道、知识引擎、搜索、图查询
- Phase 3 AI 集成完成：RAG 问答、多模型路由
- Phase 4 启动：面向终端用户的 Web 应用 V1
- 开源社区 50+ 贡献者

## 5. Non-goals（明确不做的事）

定义"不做什么"与定义"做什么"同样重要。以下事项是 Athena 明确排除的范围：

### 5.1 不在平台上托管的用户生成内容（UGC）

Athena 处理的是**已公开发布的内容**（新闻文章、学术论文、公开报告）。我们不是 Medium——不提供创作工具。我们不是 Twitter——不承载社交动态。如果个人想发表观点，去别的平台。Athena 负责理解那些已经发布的内容。

**为什么**：UGC 会引入内容审核、社区管理、滥用治理等完全不同的工程问题，稀释 Athena 的核心使命。同时，保持与内容创作的距离保证 Athena 的知识中立性——我们理解内容，但我们不生产内容。

### 5.2 不做个性化推荐信息流

Athena 提供搜索和问答，不提供"你可能感兴趣"的无限信息流。我们不和 TikTok、今日头条竞争注意力经济。

**为什么**：推荐算法的优化目标是"停留时间"，而不是"理解深度"。这与 Athena 的核心价值观（Truth over Fluency）冲突。用户来 Athena 是带着问题来的——我们回答完问题就放他们走。我们不以让他们多刷 10 分钟为荣。

### 5.3 不做实时新闻

Athena 的知识更新周期是分钟级（采集）到小时级（AI 处理），不是秒级。突发新闻的"第一个报道"交给 Twitter 和新闻社。Athena 做的是"等尘埃落定后的理解"。

**为什么**：突发新闻的准确性最差——第一条报道往往是错的。Athena 的知识图谱需要多源交叉验证，不适合秒级抢快。

### 5.4 不做付费墙和独占内容

所有 Athena 处理的内容都来自公开来源。我们不购买独家内容版权，不搭建付费墙。

**为什么**：Athena 的定位是基础设施层，基础设施不应该是围墙花园。

### 5.5 不做社交功能

没有评论、点赞、转发、关注。Athena 不是社交网络。

**为什么**：社交功能驱动的是病毒传播，而不是深度理解。它们引入的是"谁更受欢迎"的信号，而不是"谁说得更准确"的信号。

### 5.6 不做专业领域专家系统

Athena 处理通用知识，不做医疗诊断、法律建议、金融投资建议等专业领域决策。

**为什么**：专业领域需要领域特定的验证、合规和责任机制，超出通用知识平台的工程边界。Athena 可以提供"关于某疾病的已知研究"，但不提供"你应该如何治疗"。

## 6. Target Users（目标用户）

### 6.1 用户分层

Athena 的用户按介入深度分为三层：

**第一层：终端知识消费者（End Users）**

直接使用 Athena Web/Mobile 应用或集成 Athena 的第三方应用的个人用户。他们是最大的用户群。

- **典型场景**：大学生做论文研究时用 Athena 查找和溯源文献；记者调查某个事件时用 Athena 梳理实体关系脉络；医生想了解最新药物研究时用 Athena 查询结构化的论文摘要。
- **核心需求**：快速找到准确答案 + 可溯源 + 多角度
- **进入阶段**：Phase 4（Web 应用上线）

**第二层：开发者与集成商（Developers & Integrators）**

通过 Athena API 和 SDK 构建应用的专业用户。他们是生态系统的基石。

- **典型场景**：教育科技公司在其学习平台中集成 Athena 的问答 API；金融数据公司用 Athena 的实体关系 API 增强其风险评估模型；新闻 App 用 Athena 的搜索 API 提供"深度阅读"功能。
- **核心需求**：稳定、快速、文档齐全的 API + 可预测的定价
- **进入阶段**：Phase 5（开放平台）

**第三层：知识贡献者与审核者（Contributors & Curators）**

直接参与知识质量维护的用户——审核 AI 提取的声明、合并重复实体、标记过时信息。

- **典型场景**：领域专家审核其专业领域的 AI 提取结果；Librarian 标记和修正实体关系；活跃社区成员参与知识冲突的仲裁。
- **核心需求**：高效的审核工具 + 清晰的贡献影响力 + 社区认可
- **进入阶段**：Phase 3（Statement 审核工具上线）

### 6.2 用户画像（Personas）

**Persona 1: 研究型学生 (Maria)**

- 22 岁，生物学硕士在读，母语西班牙语
- 每天花 3 小时检索和阅读论文
- 痛点：80% 的论文是英文，语言障碍 + 信息过载
- Athena 价值：用母语提问获得跨语言的知识答案，每篇论文自动摘要

**Persona 2: 调查记者 (David)**

- 35 岁，调查记者，工作语言英语
- 每个调查项目需要梳理 100+ 篇文章的实体关系
- 痛点：手动建立人物/组织关系网络耗时数天
- Athena 价值：自动提取实体关系 + 时间线可视化

**Persona 3: EdTech 开发者 (Wei)**

- 28 岁，教育科技公司后端工程师，中文母语
- 正在构建一个 AI 辅导产品
- 痛点：自建知识库成本高、质量不可控
- Athena 价值：通过 API 直接获取结构化知识和可信问答

## 7. North Star Metric（北极星指标）

### 定义

**每月通过 Athena 成功解决的"有意义的求知行为"数量（Meaningful Knowledge Actions, MKA）。**

### 为什么是这个指标

北极星指标需要满足三个条件：衡量用户价值、反映产品使命、可被团队驱动。

**衡量用户价值**：MKA 衡量的是"用户带着问题来，带着有出处的答案走"的核心闭环，而不是虚荣指标（DAU/MAU/Page Views）。

**反映产品使命**：Athena 的使命是"将全球信息转化为可信知识"，MKA 直接衡量"有多少次转化成功发生"。

**可被团队驱动**：每个团队都有直接影响 MKA 的杠杆——内容团队增加源覆盖、AI 团队提升提取准确率、搜索团队降低查询延迟、平台团队提升 API 可用性。

### MKA 的定义标准

一次 MKA 需满足以下至少 3 项：
1. 用户发起了一次搜索或提问（意图明确）
2. 用户查看了至少一个实体的详情页（深度消费）
3. 用户点击了至少一个来源链接（溯源行为）
4. 用户在搜索结果中停留超过 30 秒（有意义阅读）
5. 用户通过 API 发起的调用成功返回了结果（开发者价值）

### 现阶段基准与目标

| 时间 | MKA/月 | 说明 |
|------|--------|------|
| Phase 2 | 0 | 无终端用户 |
| Phase 4 Alpha | 100K | 内部测试用户 |
| Phase 4 GA | 10M | 公开发布 |
| Phase 5 | 100M | 开放平台 + 第三方应用 |
| 2031 | 1B | 五年目标 |
| 2036 | 10B | 十年目标 |

## 9. Roadmap（路线图概览）

实现上述愿景的分阶段路径。完整详细路线图见 [15-roadmap.md](15-roadmap.md) 和 [product/roadmap.md](product/roadmap.md)。

### Phase 0 — Foundation（2026 Q3-Q4）← 当前

**目标**：建立项目治理、架构设计、技术选型。**零行代码**。

**交付**：16 编号核心文档、9 个 AI 规范文件、完整施工蓝图（BLUEPRINT）、架构审查（ADR-002）。

**状态**：95% 完成。剩余：Blueprint 最终审批。

### Phase 1 — Core Infrastructure（2026 Q4 - 2027 Q1）

**目标**：搭建技术骨架。Shared Kernel + DB Schema + Event Bus + Collector Service。不做业务功能，不做 UI。

**关键交付**：13 张 PostgreSQL 表、Redis Streams 事件总线、RSS/API/Scraper 三种源的内容采集管道、Docker 化开发环境。

### Phase 2 — Domain Core（2027 Q1 - Q2）

**目标**：实现核心知识能力。实体管理、关系管理、AI 提取管道、搜索基础设施、Neo4j 图同步。

**关键交付**：实体 CRUD + 多语言、AI NER + Entity Linking、混合搜索（全文 + 向量）、图查询 API。

### Phase 3 — AI Integration（2027 Q2 - Q3）

**目标**：深度 AI 集成。多模型路由、RAG 管道、AI 评测框架。

**关键交付**：Model Gateway（支持 3+ Provider）、知识问答引擎（含溯源）、Prompt 管理平台。

### Phase 4 — User Experience（2027 Q3 - Q4）

**目标**：面向终端用户。Web 应用、个性化引擎、移动端（TBD）。

**关键交付**：Next.js Web App、推荐引擎、知识仪表盘。

### Phase 5 — Ecosystem（2028+）

**目标**：开放平台。插件市场、公开 API、第三方集成、社区治理。

**关键交付**：插件市场、Python/TypeScript/Dart SDK、Slack/Notion 集成、开发者文档门户。

### 长期演进（2029-2036）

- 实时知识图谱更新（秒级延迟）
- 多模态理解（图像、视频、音频 → 知识提取）
- 自主 Agent 研究助手（给定课题，Agent 自主阅读论文并生成综述）
- 去中心化知识网络（多节点共享和验证知识）
- 企业级私有部署方案
